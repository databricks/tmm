# 8. How do I train and register an ML model with Genie Code?

In the [explore step](30-genie-explore.md) you labeled every aircraft's flight phase with a rule:
Ground, Climb, Descent, or Cruise, based on `on_ground` and `vertical_rate`. The rule only works
when the vertical rate is there, and ADS-B feeds don't always deliver a usable one: the
[EDA step](20-genie-eda.md) found `vertical_rate` missing in 11.9% of the 696M rows. So you ask the
data scientist's question: **can a model tell the flight phase from altitude, speed, and heading
alone?** Genie Code builds, compares, and registers that model for you, from one prompt in a
notebook.

## How does Genie Code build an ML model on Databricks?

In a notebook, **[Genie Code](https://docs.databricks.com/aws/en/notebooks/ds-agent)** works as a
data science agent: it plans a multi-step workflow, writes the cells, runs them, and reports back.
Everything it produces lands on the platform you already use:

- **[MLflow](https://docs.databricks.com/aws/en/mlflow/)** tracks every training run, with its parameters, metrics, and artifacts, so you compare models side by side.
- **[Models in Unity Catalog](https://docs.databricks.com/aws/en/machine-learning/manage-model-lifecycle/)** govern the winner with versions, lineage, permissions, and a movable `@prod` alias.
- A **gold predictions table** holds the batch-scored results for downstream use.

You train on **`silver_state_vectors_clean`** from your [pipeline](40-pipeline.md). It is already
cleaned by the data-quality expectations you derived from the [EDA findings](20-genie-eda.md), so the
data scientist starts from the data engineer's output instead of redoing the cleanup.

## Why are on_ground and vertical_rate excluded as features?

They **define the label**. A model that sees `vertical_rate` only has to relearn the rule, which
scores perfectly and teaches you nothing. That is **target leakage**. Excluding both columns
leaves `baro_altitude`, `geo_altitude`, `velocity`, and `true_track` as features, which makes this
an honest, non-trivial problem: Ground separates easily, but Climb, Cruise, and Descent overlap
without the vertical-rate signal.

## Step-by-step guide: flight-phase model with Genie Code

1. **Create a notebook.** Create a new notebook named **OpenSky flight-phase model** and open Genie Code in it.

2. **Hand Genie Code the objective and let it plan.** The prompt states the label, the allowed features, and the outputs, then asks Genie to show its plan and wait:

   ```text
   Build a flight-phase classifier on silver_state_vectors_clean, Americas only
   (longitude between -170 and -30). Label: Ground if on_ground, Climb if
   vertical_rate > 1.5, Descent if vertical_rate < -1.5, else Cruise.
   Features: baro_altitude, geo_altitude, velocity, true_track only. Do not use
   on_ground or vertical_rate as features (they define the label).
   Take a stratified sample, compare Logistic Regression, Random Forest and
   Gradient Boosting with MLflow, evaluate with macro-F1 and a confusion matrix,
   register the best model in Unity Catalog as flight_phase_model with a @prod
   alias, then batch-score into gold_flight_phase_predictions.
   Show me your plan first and wait for my go-ahead.
   ```

3. **Review the plan, then approve.** Genie Code lists its steps: label derivation, class balance check, stratified sampling, three training runs, evaluation, registration, and batch scoring. Check that the feature list excludes `on_ground` and `vertical_rate`. Expect it to ask a question back, too. State vectors are a time series, so the same aircraft appears in many rows, and a random train/test split leaks an aircraft's trajectory into both sides. Genie Code suggests splitting **by aircraft (`icao24`)** instead; take that option for honest metrics, then give the go-ahead:

   ```text
   Go ahead: use the group split by icao24 and a ~200K sample.
   ```

4. **Check the three outputs.**

   - **MLflow experiment:** open the notebook's experiment and compare the three runs on macro-F1.
   - **Registered model:** in **Catalog Explorer**, open `flight_phase_model` and confirm the `@prod` alias points at the best version.
   - **Predictions table:** query `gold_flight_phase_predictions` and compare actual and predicted phase:

     ```sql
     SELECT actual_phase, predicted_phase, COUNT(*) AS n
     FROM gold_flight_phase_predictions
     GROUP BY ALL
     ORDER BY actual_phase, n DESC;
     ```

     _(Confirm the column names in the table Genie Code creates.)_

5. **Optional: improve the model with a follow-up.** Most errors come from Climb, Cruise, and Descent looking alike at a single point in time. Ask for a feature that captures motion without leaking the label:

   ```text
   Add a feature with the change in baro_altitude per aircraft (icao24) over its
   previous few position reports, retrain the best model, and compare macro-F1
   with the previous version in MLflow.
   ```

> [!NOTE]
> The model, the MLflow experiment, and the predictions table are written to the same catalog and
> schema as your pipeline tables. The Marketplace catalog is read-only, so never register a model there.

## Results

On Free Edition, the run takes a few minutes and Genie Code verifies every claim against the cell
outputs before it reports back. From one test run on the 12:00 to 12:15 silver table:

| | |
|---|---|
| **Americas rows** | 1,731,476, of which 1,464,420 have a determinable phase (Cruise 832,832 · Climb 329,279 · Descent 260,388 · Ground 41,921) |
| **Training sample** | 192,372 rows from 1,973 aircraft, stratified so each phase holds 22 to 26% |
| **Split** | by aircraft: 1,578 train and 395 test aircraft, no overlap |
| **Test macro-F1** | Random Forest **0.774** · Gradient Boosting 0.740 · Logistic Regression 0.653 |
| **Registered model** | `flight_phase_model` version 1, alias `@prod` |
| **Predictions** | `gold_flight_phase_predictions`, 1,731,476 rows with predicted phase and confidence |

![The OpenSky flight-phase model notebook after the run: the model comparison cell shows Random Forest with macro-F1 0.7739, Gradient Boosting 0.7398, and Logistic Regression 0.6531, and the Genie Code panel summarizes the data and stratified sample, the aircraft-level split, the registration of flight_phase_model version 1 with the @prod alias, and the gold scoring of 1,731,476 rows.](assets/54-ml-results.png)

What the numbers say:

- **Random Forest wins, but not by a mile.** The tree models beat the linear baseline, most likely because flight phases don't separate along straight lines in altitude, speed, and heading.
- **Ground is easy, the airborne phases are not.** Ground scores an F1 of about 1.0. Most errors sit between Cruise and Climb or Descent: an aircraft leveling off near the ±1.5 m/s threshold looks the same at a single point in time.
- **Trust the holdout number.** The predictions table agrees with the rule-based label 97% of the time, but the final model was refit on all sampled rows, so that figure is optimistic. Genie Code points this out itself; 0.774 on unseen aircraft is the honest estimate.

Your numbers will differ from run to run, because Genie Code may pick different sample sizes and
hyperparameters. MLflow keeps every run, so the comparison stays honest.

## Machine learning on Databricks — Beyond the Basics

A few things worth knowing once the basics work:

- **[Feature Views](https://docs.databricks.com/aws/en/machine-learning/feature-store/feature-views)** — declare feature logic once, such as per-aircraft averages keyed by `icao24`, and Databricks generates both the training data and the serving pipeline, so features are never computed differently at training and serving time. Online features are served from a Lakebase-powered online store. Use it when the same features feed several models or a real-time endpoint.
- **[Model Serving](https://docs.databricks.com/aws/en/machine-learning/model-serving/)** — expose `flight_phase_model@prod` as a REST endpoint for real-time predictions. Use it when an app needs a phase per request instead of a batch table. Free Edition [limits](https://docs.databricks.com/aws/en/getting-started/free-edition-limitations) the number of active endpoints.
- **Retrain on a schedule** — add the notebook as a task after the pipeline in your [Lakeflow Job](50-job.md), or in your [bundle](52-dabs.md), so the model retrains on fresh silver data. Use it when the data drifts or new days arrive.
- **[Champion and challenger aliases](https://docs.databricks.com/aws/en/machine-learning/manage-model-lifecycle/)** — register a new version as `@challenger`, compare it with `@prod`, and move the alias when it wins. Use it when you want to swap models without changing the code that loads them.

You trained a flight-phase classifier on the pipeline's silver data from one prompt: Genie Code
planned the workflow, compared three models in **MLflow**, registered the best one in **Unity
